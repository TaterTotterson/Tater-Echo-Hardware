# Biscuit ADC3101 high-pass trial — 2026-11-14

## Scope and result

Owner-authorized kernel/filter trial on one Biscuit. The existing vendor
biquad tuning was preserved; Tater's first-order 80 Hz software filter was
replaced by an independently designed first-order section in each ADC channel.
Gain remained at the original PGA zero / unity digital / +40 dB software
staging so the filter comparison did not also change gain. No raw audio was
saved, no AGC or DSP firmware was enabled, and no boot-critical partitions were
touched beyond the already-shared recovery partition.

The default-off kernel boot passed the owner's immediate first-word/reply
check. The enabled kernel's physical coefficient readbacks produced the exact
read-only ALSA status `[1,80,255,16000]`; IDC was off. The isolated app logged
`verified hardware=true`, including after the physical mute/unmute check.
The owner passed two immediate requests, a quieter/far request, waking during
a reply, and mute blocking wake until unmuted. Nine-channel S24_3LE/16 kHz
capture stayed RUNNING with zero stalls/subscriber drops through 120 seconds;
the existing channel-8 hardware echo reference remained selected.

This is a short functional pass, **not** a measured noise-floor, CPU, latency,
ADC-headroom or AEC improvement. Longer loud-playback tests, integrated gain
plus filter qualification, Radar hardware testing and final OTA remain open.
No default-on production kernel or published firmware was created.

## Reproducibility

- C: `4d05170eb53df0a2b5a4c98b791ba2a18e667e38d2a18f3b1cda36e5bafde1b6`
- Header: `6c5e57d6132f1de8619a4afa51bc96f55e9bd45b4058abcffc2abb3bc178ebb2`

The independent coefficients are generated by
[`adc3101_filter_lab.py`](../../probes/mt8163-audio/adc3101_filter_lab.py),
using [TI SLAS553B](https://www.ti.com/lit/ds/symlink/tlv320adc3101.pdf).
They track the software one-pole magnitude within 0.004 dB from 1 Hz to
Nyquist. The exact same kernel helper is exercised by the strict fake-I2C
self-test, including partial writes/readback failures and rollback failures.

The full test kernel used the original AOSP `arm-eabi-4.8` toolchain checkout
`26e93f6af47f7bd3a9beb5c102a5f45e19bfa38a`, the pinned official source plus
the existing Bluetooth/USB/security patches, and the independent default-off
0051 overlay. Release identity: `3.18.19-bt`; kernel SHA-256:
`1f0f26faabdeee69db3d6e4ba884a27fdc60bb1a76fbc8f35f7176d73ea8ebbc`.
The new image retained the unit's exact original ramdisk, addresses, page size
and non-kernel payloads; enablement only appended
`snd_soc_tlv320aic3101.tater_hpf80=1`.

The filter-only app was based on firmware tag v4.2.3, commit
`d5b395a6e680a5b765fcd6c3339598f7d3807ff5`, and changed only the integer mixer
read interface and verified filter bypass. SHA-256:
`4ce863a1cf912c37467dba1a5050e40c564f14f5b9032baac43f003d740d8fd5`.
It used the already-qualified MWW/ORT runtime hashes rather than substituting

## Recovery and integration boundary

Before the trial, the owner physically entered independent Volume Down
bootloader fastboot; the product and 16 MiB recovery capacity were checked
without writes. The original TWRP handoff was then verified, and exact Linux
and TWRP images were privately pulled and hash-checked. No private images,
serial identifiers, calibration, certificates or vendor blobs are included here.

The original Linux image was restored and read back on disk **before** the
temporary compatible daemon ran; the enabled kernel remained only in RAM.
The bounded runner rebooted the original kernel at the end instead of
resuming the old software-filter daemon under the enabled hardware filter.
The installed app, A/B selection and saved user settings were not replaced.

Integration must preserve the application's verified-state gate and deploy the
matching kernel/application together. An old kernel continues using software
filtering. Do not claim a Radar pass or copy this unit's recovery image to
another model. The independent first-order filter is not evidence that
array-wide AEC, beamforming or wake inference can run on these stereo miniDSPs.

## Subsequent source integration

After the owner approved updating both targets, the firmware repository gained
the normal `linux/dot/build_kernel.py` entry point and the independent overlay
under `linux/dot/audio`. It builds separate Biscuit/Radar kernels from the same
pinned platform builder and GCC 4.8, enables the profile by default, and retains
the boot-time opt-out plus the application's verified-state software fallback.
`platforms/dot-audio-lock.json` pins source and reviewed kernel digests and
keeps release qualification false pending the combined/device/update checks.
The bench default-off source here remains the historical isolated experiment;
do not silently replace it with production defaults or reinterpret the trial
as a combined gain/filter or Radar hardware pass.
